# Collaber: поисковый запрос не является интро

31 октября пользователь показал живой прогон: после «Ищу разработчика» бот уточнил стек, после «Ищу разработчика по созданию мини-приложения» одновременно запросил согласие на публичный профиль и выдал двух разработчиков с прямыми контактами и интро.

## Причина и изменение

`possibleIntro` считал отдельные слова `ищу` / `looking for` достаточными для извлечения профиля. `processJob` ставил задачу INTRO до маршрутизации поиска; воркеры могли обработать один запрос и как поиск, и как профиль. Поиск без обращения к боту не попадал в предварительный маршрут Collaber и мог стать обычным разговорным ответом.

- Самостоятельный поиск без рассказа о себе больше не является кандидатом на интро. `#intro` / `#интро`, сведения о себе, проекте и предложения помощи продолжают сохраняться; потребности внутри настоящего интро разрешены.
- Предварительный фильтр применяется ещё до постановки INTRO в очередь. Извлечение также игнорирует сообщения, уже зарегистрированные как групповой поиск, включая правки с текстом о проекте.
- В основном обработчике сначала выполняется маршрут поиска и только при его отказе — сбор интро. Сбор настоящих интро при отключённых разговорных ответах сохраняется.
- Явные самостоятельные запросы вида «Ищу разработчика» могут идти в Collaber без упоминания бота. Ответ другому человеку не перехватывается; выключенный поиск и режим без автопилота соблюдаются. Указанная профессия достаточна для начала поиска; стек и бюджет не обязательны.
- Старые отложенные запросы согласия по ошибочно сохранённому поиску больше не отправляются. Разрешение на публичный показ настоящего профиля сохранено.

## Проверка

- Сборка backend, 89 тестов Community Manager и security smoke прошли.
- Полная интеграция прошла в отдельном PostgreSQL-контейнере: 62 миграции, нулевой schema diff, заглушки Telegram/AI. Новый сценарий запускает настоящий `processCommunityManagerJobs`: короткий поиск, уточнённый поиск и запрос со словами «мой проект» создают запрос Collaber, не вызывают разговорного агента, не создают INTRO/профиль и не затирают существующее интро. Проверены правка поискового сообщения, подавление старого consent prompt и сохранение явного `#intro` с потребностью.
- Изображение, оформление карточки и прямые ссылки не меняются. Новых таблиц и миграций нет.
- Текущая реальная модель проверена на четырёх синтетических фразах: короткий запрос разработчика и запрос Mini App → SEARCH; поиск без темы → CLARIFY; явно помеченное интро с потребностью → NONE для поискового маршрута. Для самопрезентации задан явный приоритет над потребностью внутри неё; дополнительный фильтр тега интро применяется до вызова модели.
