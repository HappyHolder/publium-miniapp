# Внедрение Пульса v2 — 11.10.2026

## Изменения

Общий балл, пять осей, радар и сопоставимая динамика сохранены. Реализована предложенная модель в `server/src/lib/pulseScoring.ts`. Она отделяет нормализацию, достаточность данных и исходные метрики. API возвращает расшифровки и переведённые в баллы составляющие; интерфейс не хранит отдельные «отраслевые нормы».

Сбор: долговечная уникальность сообщения + атомарные дневные счётчики, время Telegram, обогащение адресата поздним наблюдателем, классификация личностей Ядра, общий вход Moderator/Manager, дедупликация service/chat_member и учёт реального повторного вступления. Сбор Ядра выполняется до ограничения часов активности.

Добавлены проверки доступности сбора, журнал завершённых контекстных оценок с ID доказательств и архив без текстов сообщений событий модерации. Исходные тексты не копируются. Короткоживущий операционный журнал архивируется перед удалением; правки действующих событий синхронизируются при чтении отчёта.

UI: раскрытие формул, знаменателей и нормированных баллов, полный календарь MSK, отдельные состояния неизвестных данных, график именно индекса, корректные когорты и регулярность, видимая неизвестная часть стажа, отмена устаревшего запроса и ошибки загрузки без старого отчёта под новым периодом.

## Выкатка

1. Сделать штатный backup базы; применить `server/prisma/migrations/20261011090000_pulse_v2/migration.sql` через обычный `prisma migrate deploy`. Миграция только добавляет поля и таблицы; текущие счётчики не пересчитывает и не удаляет.
2. Выпустить сервер и frontend вместе: контракт отчёта v2 изменён. Prisma-клиент должен быть сгенерирован по новой схеме.
3. Перерегистрировать webhooks Moderator и Manager с `chat_member`. Скрипты `set-moderator-webhook.mjs` и `set-community-manager-webhook.mjs` обновлены для общих ботов; для персональных ботов используется существующее переподключение через UI и `setBotWebhook`. У бота должны быть административные права. Существующие webhook не менялись в ходе этой работы.
4. Проверить heartbeat `PulseCoverage` в двух соседних днях, реальные переходы join/leave и несколько реальных цепочек reply в Collaboration. Эти проверки требуют доступа к рабочему окружению; локальная фикстура их не заменяет.
5. Старое число не становится числом v2 автоматически. Пока нет достаточной непрерывной истории, карточка остаётся в состоянии накопления данных, затем показывает предварительный/полный индекс. Для полной дельты нужны два полных сопоставимых периода с пятью доступными осями.

## Принятые ограничения реализации

- Полнота оценивается по административному webhook каждые 30 минут; это доступность источника, не доказательство доставки каждого события. При доступном только GramJS сырые данные сохраняются, но полная оценка недоступна.
- Классификатор использует harassment для ненависти; требование явно добавлено в контракт контекстного анализа. Нельзя считать обычную проверку мата полным охватом климата. Неверные/неполные ответы модели не засчитываются как отрицательная проверка.
- Подписи и текст входят в аудиторию индекса; сообщения без текста, читатели, ответы без Telegram reply и неизвестные старые личности не восстанавливаются.
- Стаж остаётся ориентиром известной части списка, без заявления о полном реестре состава. Первое наблюдавшееся вступление не доказывает первое вступление за всю жизнь чата.
- Тепловая карта строится только по метаданным v2. Старая история может содержать прежде созданные приблизительные счётчики; она помечена непроверенной.
- 760 дней метаданных покрывают два годовых окна с запасом; нужно наблюдать объём таблиц и время годового отчёта на production-нагрузке. Синтетические локальные проверки не заменяют нагрузочный тест.
- Стартовые шкалы модели требуют калибровки на разных типах сообществ. Формула внедрена, статистическая валидность универсальных порогов не заявляется.

## Проверки

Финальная локальная проверка 12.10.2026:

- 184 серверных теста прошли, без пропусков и ошибок; охвачены lib, moderator и communityManager. После исправления дублирования свойства в тестовой фикстуре heartbeat её повторный целевой тест также прошёл.
- TypeScript сервера (`tsc --noEmit`) и production-сборка frontend прошли. Сборка предупреждает о существующем крупном JS-бандле (>500 КБ).
- `prisma migrate diff` между исходной и новой схемами дал ровно те же 26 SQL-операций, что и подготовленная миграция. Реальное применение к PostgreSQL локально не выполнялось.
- Браузерная проверка Пульса прошла на 320/390/768 px: полный, предварительный и недостаточный отчёт, объяснения формул, смена периода с запоздалым ответом, ошибка и повторная загрузка.
- Штатная браузерная проверка приложения прошла: Посты → Создать → Профиль, блокировка доступа без Telegram initData и запуск через tgWebAppData.

Браузерная проверка `scripts/smoke-pulse.mjs` загружает настоящий PulseTab и стили, подменяя только ответы API. Фикстуру создаёт `pulseReport.test.ts`, если задан `PULSE_FIXTURE_OUTPUT`. Проверяются ширины 320/390/768, состояния complete/preliminary/insufficient, раскрытия, гонка смены периода, ошибка и повторная загрузка. Скриншоты и результаты — в `output/pulse-implementation-2026-10-11`.

Рабочая база и Telegram webhooks в рамках локального внедрения не изменялись. Реальные цифры Collaboration из скриншотов не использовались как выдуманная полная выгрузка.
