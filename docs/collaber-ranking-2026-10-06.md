# Collaber: роли кандидатов и стабильная отправка

## Проблема

В тестовом чате запрос о проектах проверки человечности получил только разработчика-интегратора. Профиль автора сервиса присутствовал и разрешал публичный показ. Журнал показывал два независимых подбора для одного ответа: первый shortlist содержал пять профилей, второй — два. В карточку попадала цитата с общим названием профессии, выбранная по совпадениям слов, а не по основанию смысловой рекомендации.

## Изменение

- До 30 доступных профилей передаются на смысловую оценку, включая профили без буквального совпадения слов. В большей базе сохраняется ограничение shortlist до 30 с лексическим ранжированием; это не полный семантический поиск по большой базе.
- Модель возвращает решение по каждому переданному профилю: роль (поставщик/автор проекта, интегратор, ищущий партнёра, иной), соответствие (прямое, дополнительное, отсутствует), код причины и подтверждающую цитату.
- Для запроса о сервисе поставщик решения имеет приоритет перед интегратором. Для задачи подключения интегратор может быть основным кандидатом. Одинаковая потребность сама по себе не означает полезного совпадения.
- Прямые совпадения показываются перед дополнительными; максимум три результата, без обязательного заполнения всех мест.
- Цитата проверяется как непрерывный фрагмент текста именно этого профиля. Некорректный/неполный ответ модели вызывает повтор обработки, а не ложный ответ «никого нет».
- Перед отправкой AI больше не выбирает людей заново. Проверяются сохранённые кандидаты: актуальное участие в чате, контакт Telegram, разрешение на показ, неизменность содержимого профиля, недавние приглашения и ссылка на интро. Скрытый, ушедший или изменённый профиль исключается. Непосредственно перед отправкой повторно проверяются разрешения и версия содержимого.
- В диагностическом журнале сохраняются ID профиля, роль, соответствие, код причины, включение в первые три и фактический результат. Тексты интро и цитаты туда не дублируются.

Интерфейс настроек, оформление изображения и кнопки используют существующие компоненты/настройки. Новых миграций и импорта архива нет.

## Проверка

- 79 unit-тестов Community Manager, backend build и security smoke прошли.
- Production frontend build и smoke основных экранов, авторизации и Telegram fallback прошли.
- Изолированная PostgreSQL БД `publium_audit_collaber_20260921`: полный интеграционный сценарий с заглушками AI/Telegram, включая запрет AI при доставке, конкурентную отправку, отзыв публичного разрешения, изменение интро и выход участника. Production-профили не изменялись, сообщения в чаты не отправлялись.
- Реальная настроенная модель проверена на трёх запросах и четырёх полностью выдуманных профилях. Поиск сервиса поставил поставщика первым и интегратора дополнительным; запрос на подключение API поставил интегратора первым; запрос ремонта мебели выбрал мастера. Ищущий сервис участник не был выдан за поставщика. Все 3 проверки прошли, 1543 входных и 553 выходных токена.
- Реальные сохранённые интро для отдельного диагностического AI-прогона не использовались. Итог для живого тестового чата нужно подтвердить новым запросом участника после релиза; существующий ответ не изменяется автоматически.

## Ограничения

Роль и смысловая релевантность остаются оценкой модели. Проверка цитаты защищает от выдуманного текста, но сама по себе не доказывает правильность смысловой классификации. Специфические возможности проекта (например, anti-bot вместо общей верификации) нельзя утверждать без источника; карточка предлагает уточнить их у автора.
