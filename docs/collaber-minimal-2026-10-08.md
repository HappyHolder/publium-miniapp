# Collaber: компактный формат группы

## Исправление настроек оформления, 8 октября

Описанное ниже принудительное отключение обложки и дополнительных кнопок в группе отменено. Вернули прежний блок «Оформление сообщения»: сохранённые обложка, вступительный текст и переключатели кнопок снова применяются и в группе, и в личном диалоге. Это общие настройки, как до изменения интерфейса; отдельные настройки для двух каналов не добавлялись. Значения в базе не сбрасываются.

В группе остаются короткие описания и максимум два человека. Минимальное оформление можно выбрать существующими переключателями: отключить обложку и лишние кнопки, оставить интро; вступление можно очистить. Исправления поиска, уточнения ответом и подтверждения согласия через редактирование сохранены. Ранее отправленные сообщения не переписываются.

Проверки исправления: 81 unit-тест, backend build и security smoke, frontend production build и smoke, полный интеграционный сценарий в изолированной БД с заглушками AI/Telegram. Добавлена проверка каждого переключателя оформления группового ответа. Файл панели совпадает с версией `04d0358`; production frontend снова собирается в `index-e5v27kE4.js`.

Ниже — история предыдущего релиза; утверждения о безусловном отсутствии обложки и кнопок больше не описывают текущее поведение.

## Изменения

- В групповых ответах максимум два человека, короткая цитата из интро (до 220 символов) и одна кнопка интро на человека. Нет изображения, длинного вступления, дат, оценок и кнопок знакомства. Дополнительное совпадение явно отмечено.
- Настройки изображения и дополнительных кнопок сохранены для личного подбора. В панели показаны отдельные примеры группового и личного ответа, с существующими цветами и компонентами Publium.
- После выбора публичной/личной видимости редактируется исходное сообщение согласия, кнопки убираются. Отдельное подтверждение в чат не отправляется. Повтор после ошибки редактирования не теряет сохранённое разрешение и не создаёт новое предложение.
- Ответ на подбор того же участника в том же чате в течение суток использует предыдущий запрос как контекст уточнения. Контекст чужого подбора не подхватывается.
- Правила смыслового отбора исключают далёкие дополнительные услуги: маркетинг, дизайн и инвестиции сами по себе не отвечают на запрос о сервисе верификации. Учитываются ограничения «именно», «только», «не разработчик».

Уже отправленные подборки автоматически не переписываются. Изменения применяются к новым запросам; профили и настройки участия не сбрасываются. Импорт архива и рассылка приглашений при выкладке не выполняются.

## Проверки

- 80 unit-тестов Community Manager, backend build, security smoke.
- Production frontend build и smoke (основные экраны, авторизация и Telegram fallback). Первый запуск браузера завершился тайм-аутом навигации; повтор прошёл без изменения приложения.
- Полный сценарий в изолированной БД `publium_audit_collaber_20260921` с заглушками AI/Telegram: компактные кнопки, отсутствие обложки, согласие через редактирование, повтор после ошибки редактирования, уточнение своего и исключение чужого контекста, отказ от показа, дедупликация и отсутствие совпадений.
- Реальная модель на четырёх полностью выдуманных профилях: пять запросов (сервис, интегратор, маркетолог, только готовый сервис, отсутствующий специалист) прошли. 3201 входной и 1103 выходных токена. Реальные интро не использовались для диагностического AI-прогона.
- Локальная визуальная проверка панели на ширине 320 и 390 px через установленный Playwright; снимки в `output/playwright/collaber-minimal-*.png`. Сохранён стиль проекта. CLI недоступен из-за ошибки доступа к npm registry, использована установленная библиотека без установки пакетов.

## Ручная проверка после выкладки

В Test Publium Chat с аккаунта, отличного от автора нужного интро:

1. Запрос о проектах проверки человечности — короткая выдача, до двух интро, без картинки и маркетолога.
2. Ответ на неё «Нужен именно готовый сервис, не разработчик» — сужение результата с сохранением темы.
3. Отдельный запрос о маркетологе — профиль маркетолога.
4. Задача без специалиста в базе — короткое сообщение без выдуманных людей.
5. Новое тестовое интро — один запрос разрешения, редактирование после выбора, затем короткое предложение только при подходящем совпадении и разрешённых инициативах.
