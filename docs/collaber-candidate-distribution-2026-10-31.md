# Выдача Collaber при большом числе подходящих участников

Реализовано 31 октября 2026. Пять кандидатов на страницу, общий поиск в группе и личке, учёт подтверждённых показов.

## Цель

Участник быстро получает несколько полезных контактов, может посмотреть другие варианты и уточнить задачу. Среди сопоставимых кандидатов рекомендации распределяются с учётом предыдущих показов. В группе сохраняется компактная выдача и прямые кнопки «Написать» / «Интро».

## Поведение до этого изменения

- В группе максимум два кандидата, в личке — три.
- Из базы формируется короткий список до 30 профилей, модель принимает решение по каждому. После проверки доступа функция возвращает только 2/3 кандидата; остальные не сохраняются в запросе для дальнейшего просмотра.
- У выданных кандидатов после подтверждённой отправки обновляется `lastProposedAt`. Поле используется при равенстве поискового балла до смысловой проверки и также связано с инициативами. Гарантированную ротацию после ранжирования оно не обеспечивает.
- Уточнение и обратная связь есть; «Показать ещё» и история страниц отсутствуют.

## Реализованное поведение

### Соответствие задаче

1. Учитывать предмет запроса, специализацию, подтверждённые предложения помощи и ограничения автора.
2. Исключать самого автора, скрытые/удалённые профили и ушедших участников. В группе обязательно разрешение на публичные рекомендации.
3. Конкретный опыт для задачи имеет приоритет. Учёт показов применяется среди сопоставимых кандидатов, а не поднимает менее подходящего человека ради очередности.
4. Общего запроса «ищу маркетолога» достаточно для первого подбора. Уточнение специализации доступно по желанию; обязательной анкеты нет.

### Компактный ответ и просмотр следующих вариантов

- Группа и личка: до пяти людей, у каждого краткое основание и парные кнопки «Написать» / «Интро».
- «Продолжить в личке» открывает тот же запрос через подписанную ссылку. Бот показывает следующие варианты после нажатия пользователем Start; уже просмотренные в группе исключаются. Публичный поиск сохраняет публичную область видимости и в личке. Автоматической рассылки нет.
- «Ещё варианты» появляется, если есть не показанные кандидаты либо следующая часть поиска.
- В группе кнопка доступна автору запроса и обновляет существующую карточку, не создавая очередное сообщение. Перед заменой сохраняется информация о том, какой текст/подпись и клавиатура были отправлены; тип сообщения и оформление не переопределяются текущими настройками.
- Для возврата к уже показанной странице — «Назад». Возврат не считается новым показом для ротации.
- Повторное нажатие старой кнопки и два быстрых клика не перескакивают через страницу. В callback указываются запрос и ожидаемая версия страницы; сервер принимает один переход.
- Уточнение создаёт обновлённую задачу с сохранением исходного контекста. Подходящий прежний кандидат может остаться, если новое условие делает его предпочтительным.
- После исчерпания подходящих людей не подставлять повторных или слабые совпадения для заполнения пяти мест. Последняя страница может содержать одного человека.

### Распределение рекомендаций

- Сначала соответствие задаче; затем для сопоставимых профилей меньше подтверждённых публичных показов в этом сообществе за последние 30 дней; затем более давний последний показ.
- История показов конкретному автору используется для снижения повторов в новых похожих запросах. Уже просмотренных в одном поиске исключать из следующих страниц полностью.
- Новые подходящие профили с нулём показов участвуют в распределении на общих основаниях. Активность в переписке и длина интро не являются оценкой качества специалиста.
- Равенство оставшихся условий разрешать сохранённым порядком смыслового отбора. После перезапуска страницы порядок не меняется.
- Частные просмотры списка не должны исчерпывать возможность человека появиться в публичной группе. Публичные и личные показы учитывать отдельно.
- Показ означает подтверждённую доставку карточки, а не предпросмотр владельца, загрузку пула, клик по «Назад» или ошибку Telegram. Прямой URL «Написать» не даёт достоверной информации о том, состоялся ли контакт; не считать показ успешным сотрудничеством.
- Это предпочтение при выборе, без жёсткого запрета рекомендовать сильного кандидата повторно в течение 30 дней.

## Сохранение и актуальность

Для каждого поиска сохранять задачу, проверенный смысловой отбор и его порядок, доказательные цитаты и версии профилей, просмотренные страницы и текущую версию карточки. Историю подтверждённых показов хранить отдельно от текущей страницы и от `lastProposedAt`, используемого инициативами. Удаление профиля должно очищать производные данные и показы, связанные с ним.

Перед каждой новой выдачей заново проверять участие, видимость, текущий username и совпадение версии интро. Удалённого/ушедшего/отозвавшего разрешение кандидата пропускать и брать следующего. Ошибку проверки доступа не трактовать как отсутствие совпадений.

Доставка/редактирование и сохранение страницы должны быть защищены от повторной отправки и параллельных callback. Неопределённый результат Telegram требует существующего сценария проверки, а не слепого повторного перехода.

Навигация доступна автору в течение семи дней. Переход в личку и возврат в группу используют общую историю просмотренных людей; страницы каждой карточки можно листать назад. Повторное открытие ссылки не отправляет уже созданную личную карточку заново.

История показов за последние 30 дней влияет на распределение. Минимальные связи показов с профилями сохраняются также для очистки производных данных при удалении профиля. Ошибка Telegram с неопределённым результатом блокирует дальнейшую выдачу этой семьи запросов до проверки; подтверждённая доставка с несохранённой страницей восстанавливается по журналу без повторного вызова Telegram.

## Масштаб и стоимость

Смысловой отбор выполняется для ограниченной части кандидатов и сохраняется. Обычное переключение страницы не вызывает модель заново. Если релевантных профилей больше размера первой части, продолжать отбор следующей части с исключением уже рассмотренных. Исчерпание первых 30 профилей не означает, что в сообществе других подходящих людей нет. Не выводить точный общий счётчик до проверки соответствующего количества кандидатов.

Для чата на 1000+ участников проверить, что ограничение короткого списка не лишает целые группы специалистов доступа к выдаче. Распределение показов необходимо учитывать и при отборе сопоставимых профилей в короткий список, а не только после него.

## Приёмка

| Случай | Ожидаемый результат |
| --- | --- |
| 25 подходящих маркетологов в одном поиске | Пять страниц по пять, без повторов при неизменной доступности |
| 1 подходящий человек | Один контакт, без искусственного заполнения |
| 0 подходящих | Честный пустой результат, без выдачи людей другой профессии |
| Узкая задача, один явный специалист | Приоритет подходящему опыту независимо от числа предыдущих показов |
| Сопоставимые кандидаты, несколько новых запросов | Распределение с учётом недавних подтверждённых показов |
| Два быстрых клика / повтор webhook | Один переход, без пропуска страницы и двойного учёта |
| Кнопку нажал другой участник | Общая карточка не изменяется |
| Кандидат вышел или скрыл профиль между страницами | В следующую выдачу не попадает; используется резерв |
| Другие кандидаты находятся за пределами первых 30 | Возможен следующий отбор, нет ложного «других нет» |
| Предпросмотр владельца / возврат назад / ошибка отправки | Не создают новый публичный показ |
| Импортированная база и нативно собранная база | Одинаковые правила выбора и видимости |

В этот объём не входят рейтинг людей, оценки профессионального качества, знакомства через бота, передача контактов по согласию и автоматические личные приглашения.
